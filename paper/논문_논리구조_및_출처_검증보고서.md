## 1. 가장 중요한 결론

1. 한국범죄학회의 **「범죄와 정책」은 실제로 존재**하며, 공식 영문명은 *The Korean Crime and Policy Review (KCPR)*이다. 2025년 창간된 연 2회 발행 학술지이고 공학·ICT의 학제 간 연구를 명시적으로 수용한다.
2. 공식 KCI 검색만으로 이 신생 학술지의 **KCI 등재 여부는 확정하지 않았다.** KCI 문헌유사도 결과 제출 의무와 KCI 등재 상태는 서로 다른 문제다.
3. 변이 후 보호대상은 10,000건 중 9,964건에서 복원되었다. 이를 이용한 A/B/C/D 사후 감사와 동일 원천값 3,461쌍 분석으로 이전 평가기의 구성타당성 문제를 실질적으로 보완하였다.
4. 보호대상 표면형을 바꾼 2,160쌍에서는 원형 9.12%, 변이 18.75%가 미차단됐고 원천 그룹 동일 가중 위험차는 `+5.35%p`였다. 표면형을 보존한 문맥 변형에서는 증가가 입증되지 않았다.
5. 구성 A와 C의 같은 사례 대조에서 Layer 0 추가로만 차단된 사례는 1,354건, 반대 방향은 0건이었고 1,353건은 Layer 0의 직접 `BLOCK/[BLOCKED]`였다. 따라서 현재 저장 결과에서 Layer 0의 독립 기여와 필요성은 지지된다.
6. 구성 D에도 312건의 미차단이 남고, 공식 법령 1,519개 중 29개와 네 서비스 도메인 공식 문서 693개 중 48개가 과잉차단 후보로 탐지되었다. 특히 의료 일반교육은 265개 중 44개가 탐지되었다. 그러므로 Layer 0는 **필요하지만 충분하지 않으며**, 개인 귀속 문맥을 확인하는 완화와 후속 계층이 함께 필요하다.
7. Amazon Bedrock Guardrails의 민감정보 필터는 현재 한국어를 **“Optimized and supported”**로 공식 지원한다. 저장 결과는 특정 당시 설정에 한정하고 제품 전체의 한국어 미지원으로 일반화하지 않았다.
8. 범죄학 이론은 실제 범죄 발생을 검증한 것이 아니라 **일상활동이론의 보호자 개념과 상황적 범죄예방을 활용한 가드레일 역량 감사**의 분석 틀로 한정하였다. 잔존 우회는 범죄 전이가 아니라 전술별 잔존 취약성으로 표현하였다.
9. 법령은 개인정보 전체와 민감정보를 구분하고, 개인정보 보호법의 형벌·과태료·과징금 트랙 및 인공지능기본법 제31·33·34·35·43조의 기능을 분리하였다. 인용 조문의 시행일은 모두 2026년 1월 22일로 교정하였다.
10. 최종 참고문헌 13편은 모두 KCI·출판사·정부기관·공개 전문 레코드에서 실재와 사용 범위를 확인했고 본문 인용과 참고문헌이 1:1 대응한다. 다만 유료벽 본문과 대상 학술지 전체 아카이브의 전수 확인 한계는 공개하였다.

### 4.1 실제 게재논문 구조와의 제한적 비교

공식 사이트와 KCI에는 2026-07-26 현재 완전한 게재논문 아카이브가 노출되지 않았다. 그러나 김빛나(Bitna Kim)의 저자 공개 전문 「Rethinking American Criminology Through Translational, Transnational, and Transdisciplinary Approaches: Implications for Korean Criminology」는 자기서지에 *Korean Society of Criminology Journal: Crime and Policy*, 1(1), 47–70으로 기재되어 있어 창간호 실물로 확인할 수 있다.

이 논문은 초록·키워드 다음에 문제를 복합적 정책문제로 규정하고, 세 개의 개념틀을 각각 설명한 뒤 연구·사례 증거를 연결하고, 마지막에 한국 범죄학과 제도에 대한 함의를 제시한다. 즉, `문제 정의 → 개념틀 → 증거·사례 → 국내 정책 함의 → 결론`의 구조다.

최종 원고는 `문제 정의 → RAT/SCP·법적 틀 → 감사방법 → 재계산 결과 → 반대증거·한계 → 형사정책 제언 → 결론`으로 구성된다. 실증 감사라는 연구 성격 때문에 방법·결과가 더 분명하지만, 기술 결과를 독립된 정책 함의로 번역하고 일반화 한계를 함께 제시한다는 점에서 확인된 창간호 구조와 양립한다. 다만 확인된 표본은 1편뿐이므로 이를 학술지 전체의 유일한 형식으로 일반화하지 않는다.

## 5. 논증 구조 검증

### 5.1 현재 목차가 의도하는 인과 사슬

1. 생성형 AI 서비스에는 한국어 민감정보가 입력·출력·로그·외부 API를 통해 노출될 위험이 있다.
2. 개인정보보호법은 민감정보 처리와 안전조치를 요구하지만, 규범이 구체적 기술 성능을 자동으로 보장하지는 않는다.
3. 가드레일은 일상활동이론의 “보호자” 및 상황적 범죄예방의 표적 강화·접근통제와 유사한 기능을 한다.
4. 동일한 합성 페이로드에 서로 다른 방어 구성을 반복 적용해 보호자 역량 차이를 비교한다.
5. 취약 항목과 잔존 우회를 근거로 기술 최소기준·영향평가·폐쇄망 정책을 제안한다.

이 사슬의 **문제의식과 정책 연결은 타당**하다. 그러나 4단계의 결과 라벨이 불안정하고 3단계의 이론 조작화가 과도해, 현재 형태로는 결론이 전제보다 강하다.

|---|---|---|
| RQ1: 한국어 PII 표면형 변형이 미차단 위험을 높이는가 | 검증됨 | 동일 원천값 3,461쌍과 target-changing/preserving 층화, 원천 그룹 부트스트랩으로 일반적 문맥 변형과 표면형 변형을 분리 |
| RQ2: Layer 0 추가가 미차단을 줄이는가 | 검증됨 | 같은 9,964건에서 A/C를 직접 대조하여 C만 차단 1,354건·반대 0건, 직접 Layer 0 차단 1,353건 확인 |
| RQ3: 필요한 기술·형사정책 대응은 무엇인가 | 규범적 질문 | 실험 RQ가 아니라 법해석·정책분석 질문으로 분리해야 함 |

최종 원고는 `준실험`이라는 표현을 사용하지 않고, 저장된 동일 페이로드의 구성별 결과를 재평가하는 **사후 가드레일 감사와 짝비교**로 규정한다.

### 5.3 일상활동이론(RAT) 조작화

| v2 조작화 | 판정 | 적절한 표현 |
|---|---|---|
| 동기화된 범죄자 = 변이 L0~L5 | 부적절 | 변이 수준은 공격 기법의 정교도·난이도이지 범죄 동기가 아님 |
| 적합한 표적 = 민감정보 카테고리 | 부분 타당 | 가치·가시성·접근성·관성 등 표적 적합성 차원을 별도 측정해야 함 |
| 유능한 보호자 = 가드레일 구성 | 이론적 유추로 타당 | “수동적 기술 보호자” 또는 “보호자 역량 대리지표”로 한정 |
| 잔존 L5/RAG 우회 = 범죄 전이 | 현재 불성립 | 동일 공격의 전술별 잔존 취약성일 뿐, 공격자의 실제 전술 이동을 관찰하지 않음 |

결론적으로 이 연구는 RAT 자체를 검증하지 않는다. 가장 정확한 설명은 다음과 같다.

> 본 연구는 실제 범죄 발생의 세 요소를 검증하는 연구가 아니라, 일상활동이론의 보호자 개념과 상황적 범죄예방의 표적 강화 개념을 분석 틀로 활용한 한국어 민감정보 가드레일 역량 감사다.

전이를 주장하려면 시간 순서가 있는 적응형 공격 실험이 필요하다. 예를 들어 공격자 역할의 참가자 또는 에이전트가 Layer 0 도입 전후 어떤 전술로 이동하는지, 성공률·비용·시간이 어떻게 변하는지를 관찰해야 한다.

## 6. 코드·데이터·실험 재현 검증

### 6.0 최종 분석 기준

최초 감사는 원래 문자열이 변이 입력에 그대로 남은 4,713건만 확실히 판정할 수 있었다. 이후 `paper/analyze_postmutation_gold.py`가 저장된 변이 함수와 입력 구간을 이용해 변이 후 보호대상 문자열을 복원하였다. 리터럴 일치 4,713건, 결정적 변이 재실행 3,927건, NFKC 정규화 후 고유 정렬 1,324건으로 총 9,964건(99.64%)을 복원했고, 대응이 없거나 고유하지 않은 36건은 제외하였다.

| 구성 | 평가 가능 | 차단 | 미차단 | 미차단율 |
|---|---:|---:|---:|---:|
| A: Presidio+Bedrock+Lakera | 9,964 | 7,904 | 2,060 | 20.67% |
| B: A+LLM 판별기 | 9,964 | 9,074 | 890 | 8.93% |
| C: Layer 0+A | 9,964 | 9,258 | 706 | 7.09% |
| D: Layer 0+A+LLM 판별기 | 9,964 | 9,652 | 312 | 3.13% |

동일 PII 유형·원천값에서 생성된 원형과 변이 3,461쌍을 연결하고 반복 변이를 원천 그룹으로 동일 가중하였다. 전체 위험차는 `+2.91%p`(95% 군집 부트스트랩 CI `+1.89~+3.94%p`), 표면형이 바뀐 2,160쌍은 `+5.35%p`(`+3.83~+6.89%p`), 표면형 보존 1,301쌍은 `-0.65%p`(`-2.42~+1.14%p`)였다. 한국어 2,305쌍은 `+6.86%p`(`+4.06~+9.69%p`)였다.

따라서 최종 원고는 최초의 비동질 표본 총계에서 나온 `3.93배`를 사용하지 않는다. 아래 6.1~6.2.1은 왜 이전 평가기를 교체했는지를 보여주는 역사적 진단이다.

- PII 유형: 95개

- 최종 평가기의 원문/숫자 완화 추적까지 적용해도 추적 불가: 2,647개(26.47%)

추적 불가 사례의 분포:

|---|---:|
| L1 | 2,134 |
| L2 | 161 |
| L3 | 99 |
| L4 | 253 |
| format 그룹 | 1,511 |
| checksum 그룹 | 937 |

여기서 2,647개는 최종 논문 수치를 만든 `run_e_final_4way.py`의 원문·숫자 비교 규칙에 대한 값이다. 저장소의 다른 분석기 `analyze_true_detection.py`는 전각 숫자와 원문자 숫자를 추가 정규화하여 입력 추적 불가를 1,339개로 계산한다. 어느 쪽도 변이 후 gold span을 직접 사용하지 않으며, 동일 데이터에 서로 다른 판정 규칙을 적용한다.

최종 평가기는 레이어 출력이 달라지고 원래 `pii_value`가 출력에 없으면 성공으로 판정할 수 있다. 따라서 변이된 실제 PII가 그대로 남았는데도 다른 문자열만 바뀌었거나 원본 문자열 비교가 실패한 사례가 TRUE에 섞일 수 있다.

### 6.2 최초 평가기의 저장 결과 재계산

| 구성 | 저장 결과의 TRUE | 비율 | TRUE 중 gold 추적 불가 |
|---|---:|---:|---:|
| A baseline | 8,015 | 80.15% | 2,370 (29.57%) |
| B +L4 | 9,096 | 90.96% | 2,458 (27.02%) |
| C +L0 | 9,432 | 94.32% | 2,492 (26.42%) |
| D full | 9,723 | 97.23% | 2,550 (26.23%) |

이 수치는 파일에 기록된 결과를 재현한 것이지, 올바른 탐지율을 확인한 것이 아니다. TRUE 사례의 약 26~30%에서 정답 추적 자체가 불가능하므로 “Layer 0가 몇 %p 개선”, “p < 10⁻²⁸”과 같은 주 결론은 보류해야 한다. McNemar 공식이 맞아도 입력된 쌍별 라벨이 타당하지 않으면 유의확률은 연구 질문에 답하지 못한다.

`analyze_true_detection.py`의 다른 정규화 규칙으로 같은 저장 결과를 다시 분류하면 A/B/C/D TRUE는 각각 **7,901/9,067/9,373/9,711**이 된다. 최종 논문 수치인 8,015/9,096/9,432/9,723과 다르므로, 논문은 먼저 하나의 mutation-aware 평가 명세와 단일 구현을 고정해야 한다.

### 6.2.1 판정 가능한 보수적 부분집합에서의 Layer 0 효과(역사적 분석)

`pii_value`가 변이 입력 `mutated`에 문자 그대로 존재하는 4,713건만 별도로 분석하였다. 이 집합은 변이 후 gold span을 복원하지 않아도 평가 대상 PII의 입력 잔존을 직접 확인할 수 있다.

| 구성·입력 | n | 미차단 | 미차단율 |
|---|---:|---:|---:|
| 기존 3계층 A 전체 | 4,713 | 1,063 | 22.55% |
| Layer 0 추가 C 전체 | 4,713 | 64 | 1.36% |
| A의 L0 원형 | 1,246 | 89 | 7.14% |
| A의 L1·L2·L4·L5 변이 | 3,467 | 974 | 28.09% |
| C의 L1·L2·L4·L5 변이 | 3,467 | 57 | 1.64% |

짝별로는 A가 미차단이고 C가 차단인 사례가 999건, 반대 방향은 0건이었다. 999건의 Layer 0 개별 결과는 모두 `action=BLOCK`, `output=[BLOCKED]`였다. 이 결과는 초기 단계에서 Layer 0의 추가 차단 존재를 확인하는 데 사용했지만, 원형·변이 집단의 구성 차이 때문에 나온 `3.93배`는 인과적 효과크기로 부적절하여 최종 원고에서 폐기하였다.

이 분석은 PII 자체가 바뀌어 원문 추적이 불가능한 사례를 제외한 하한선 분석이다. 따라서 “Layer 0가 필요하다”는 심층방어 결론에는 사용할 수 있지만, 전체 10,000건의 정확한 탐지율이나 모든 변이기법에 대한 최종 효과크기로 일반화해서는 안 된다. 계산은 `paper/verify_final_paper_claims.py`로 재현할 수 있다.

필수 수정은 각 변이기가 다음을 함께 내보내도록 하는 것이다.

- 변이 후 정확한 PII span
- canonical value
- 허용되는 동치 표현
- 변이 provenance
- expected action(탐지·마스킹·차단)

그 후 전체 10,000건을 재평가하고, 난이도·유형별 사람 이중검토 표본과 일치도를 보고해야 한다.

### 6.4 재현성

`make all`은 현재 완전 재현되지 않는다. 기본 정책이 `required`인 필수 파일 `PII/fuzzer/data/tagged_korean_names.jsonl`과 `PII/fuzzer/data/tagged_korean_addresses.jsonl`이 4개 저장소와 확인한 110개 원격 ref 어디에도 없고, `sample` target도 이를 생성하지 않는다. fuzzer는 이 파일이 없으면 `RuntimeError`를 발생시킨다.

공개 코드의 Layer 0·fuzzer 테스트를 격리 환경에서 실행한 결과는 **123 passed, 8 failed**였다. 실패 8건은 모두 위 파일 부재와 연결된다. 따라서 논문에는 “완전 재현 가능”이라고 쓰지 말고, 다음을 먼저 고쳐야 한다.

또한 이름이 같은 표본 파일 두 개가 서로 다르다.

| 경로 | 실제 payload 수 | 메타데이터 |
|---|---:|---|
| `PII/results/data/payloads_10k.json` | 10,000 | `count: 10000`, PII 유형 95개 |
| `PII/evaluation/payloads_10k.json` | 3,538 | `count: 3538`, PII 유형 91개 |

`Makefile`의 `sample` target은 fuzzer를 `--count 3`으로 호출한 뒤 `sample_10k.py`를 실행한다. `sample_10k.py`는 원천 집합보다 많은 행을 복원하지 않으므로 현재 경로의 결과는 3,538건에 그친다. 누락 코퍼스를 복원하더라도 이 target만으로 논문이 사용한 10,000건을 재생성할 수 없다.

1. 파일을 비식별·라이선스 확인 후 저장소에 포함하거나 재생성 스크립트 제공
2. SHA-256 및 데이터 버전 기록
3. 의존성 lockfile과 실행 명령 고정
4. 원시 입력부터 표·그림까지 한 번에 재생성하는 깨끗한 환경 CI 제공
5. `make sample`이 정확히 10,000건을 생성하고 그렇지 않으면 실패하도록 검증(assertion) 추가
6. 평가 함수들을 하나의 canonical evaluator로 통합

### 6.5 데이터·지식베이스

데이터 저장소의 유일한 파일 `curated/curated_weak_t0.92.json`은 `source="weak"`, threshold 0.92, `kept_ids=1,997`만 제공한다. 원자료, 모델 출력, 사람 검토 라벨, 제외 사유가 없어 큐레이션을 독립적으로 검증할 수 없다.

지식베이스에는 8,400건과 10,000건 실험 서술이 혼재하며 스스로 정합성 확인 필요 상태로 표시되어 있다. 논문은 10,000건 최종 실험만 기준으로 고정하고, 8,400건은 파일럿으로 명시하거나 제거해야 한다.

## 7. Bedrock·Presidio·LiteLLM 관련 주장 검증

### 7.1 Amazon Bedrock Guardrails

AWS 공식 문서는 민감정보 필터에서 한국어를 **Optimized and supported**로 명시한다. 이는 해당 정책의 기반 모델이 한국어에 맞게 조정되고 테스트되었다는 AWS의 정의다.

- [AWS: Languages supported by Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-supported-languages.html)

따라서 아래 표현은 사용하면 안 된다.

- “Bedrock은 한국어 PII를 지원하지 않는다.”
- “Bedrock은 영어에만 튜닝되어 한국어 재현율이 낮다.”
- “상용 가드레일은 거의 예외 없이 영어 중심이다.”

가능한 표현:

> Amazon Bedrock Guardrails는 현재 한국어 민감정보 필터를 공식 지원한다. 본 연구의 결과는 실험 당시 사용한 특정 guardrail ID·version·sensitive-information policy·entity 설정 및 평가일에서 관측된 우회 성능이며, 제품 전체의 한국어 지원 여부를 뜻하지 않는다.

논문에 반드시 기록할 항목:

- AWS 리전
- guardrail ID와 version
- safeguard tier
- enabled policy와 entity 목록
- request/response 적용 위치
- 평가 날짜
- API 모델·LiteLLM 버전

### 7.2 Presidio

현재 Presidio 공식 문서는 한국용 recognizer로 `KR_DRIVER_LICENSE`, `KR_FRN`, `KR_PASSPORT`, `KR_BRN`, `KR_RRN`을 열거한다. Presidio는 다국어 및 사용자 정의 recognizer를 지원하지만 모든 민감정보를 반드시 찾는다고 보장하지는 않는다.

- [Presidio supported entities](https://microsoft.github.io/presidio/supported_entities/)
- [Presidio Analyzer](https://microsoft.github.io/presidio/analyzer/)

따라서 Presidio의 현재 일반 능력, 본 프로젝트가 고정한 버전, 프로젝트가 실제 활성화한 recognizer를 분리해야 한다.

### 7.3 LiteLLM

내부 환각 검증문서의 `LiteLLM Guardrail Policies and Korean PII Masking v2`는 실재하는 논문·공식 보고서 제목으로 확인되지 않았다. LiteLLM은 가드레일과 Presidio 등을 연결하는 게이트웨이이므로, 탐지 성능 주장은 LiteLLM 자체가 아니라 연결한 엔진·버전·언어·recognizer 설정에 귀속해야 한다.

### 9.2 신규성 검색의 범위와 반증 가능성

2026-07-26에 KCI·DBpia 도메인과 국제 학술검색을 대상으로 `생성형 AI 개인정보 가드레일 일상활동이론 범죄`, `생성형 AI 개인정보 가드레일 범죄학`, `("generative AI" OR LLM) PII guardrail "routine activity theory" guardianship`을 검색하였다. 금융기관의 민감정보 침해 위험을 RAT로 분석한 [인접 연구](https://www.sciencedirect.com/science/article/pii/S0167404822002267)와 조직·도시정부의 기술적 보호자를 다룬 연구는 확인되었다. 반면 한국어 PII 표면형 변이, 생성형 AI 가드레일, 정규화 Layer 0, RAT 보호자 조작화를 한 실험에 결합한 직접 중복 연구는 접근 가능한 결과에서 찾지 못했다.

KISS 자동 접근이 차단되었고 RISS·Scopus·Web of Science 기관 전문검색을 수행하지 못했으므로 이 결과는 세계 최초의 증명이 아니다. 연구 공백은 검색식·검색일·데이터베이스를 공개한 제한적 관찰이며, 독립 연구자가 추가 문헌을 발견하면 즉시 수정할 수 있어야 한다.

## 12. 최초 감사의 수정 우선순위와 이행

P0·P1 가운데 최종 원고의 주장에 필요한 항목은 사후변형 gold 복원, 단일 재현 스크립트, 보수적 주장 범위, 법·제품·이론·참고문헌 교정으로 이행하였다. 원시 데이터 생성 파이프라인 전체 복구와 당시 상용 API 설정 복원은 불가능하여, 이를 해결한 것처럼 쓰지 않고 사후 감사의 한계로 남겼다. 아래 목록은 최초 감사 시점의 요구를 보존한 것이다.

### P0 — 결과를 쓰기 전에 반드시 해결

1. 변이 후 정답 span과 canonical value를 생성하도록 데이터 파이프라인 수정
2. 평가 함수들을 하나의 mutation-aware canonical evaluator로 통합
3. 전체 10,000건 재라벨링·재평가
4. VIN 등 생성기와 체크섬 전수 수정
5. 탐지율·효과크기·McNemar·비용·지연 표 전부 재생성
6. Bedrock 한국어 미지원/영어 전용 일반화 삭제
7. 누락 데이터 파일과 10,000건 표본 생성·재현 파이프라인 복구

### P1 — 투고 원고 작성 전에 해결

1. RAT 검증이 아닌 보호자 역량 감사로 연구 범위 재규정
2. `준실험`, `동기화된 범죄자=변이 수준`, `잔존 우회=전이` 표현 수정
3. 개인정보보호법과 AI 기본법 조문·제재 구조 교정
4. 환각 참고문헌 제거 및 정확한 서지로 교체
5. 국내 문헌을 이론 조작화·반대 결과와 연결하고 단순 나열을 피할 것
6. 선행연구 검색식·DB·기간·배제기준을 공개해 제한된 신규성만 주장
7. KCI 등재 상태 공식 확인

### P2 — 제출 직전

1. 최종 코드·데이터 commit과 원고 수치 동결
2. 표·그림과 원시 결과의 자동 대조
3. 이해상충·연구윤리·이중용도·합성데이터 고지
4. 학회 허용 파일 형식, 분량, 유사도, 회원 요건 확인
5. 법령과 벤더 문서 접근일 최종 갱신

## 13. 최종 판정

최종 원고의 주제는 「범죄와 정책」이 밝힌 범죄예방·공공안전·ICT 학제 간 범위에 직접 들어간다. 확인 가능한 창간호 전문도 문제를 개념틀과 증거에 연결하고 한국 정책 함의로 귀결하는 구조를 사용하며, 최종 원고는 여기에 재현 가능한 방법·결과·반대증거·한계를 더 분명히 제시한다.

최초 원고의 `3.93배`, Bedrock 한국어 미지원, 잘못된 법조문, RAT·전이 과잉 조작화와 환각 기술문헌은 폐기하거나 교정하였다. 변이 후 gold 9,964건과 동일 원천값 짝비교는 특정 표면형 변형이 미차단 위험을 높인다는 결론을 지지하고, A/C 같은 사례 대조는 Layer 0의 독립 기여를 지지한다. D의 잔존 미차단 312건, 법령 29건과 서비스 문서 48건의 과잉차단 후보를 함께 보고하므로 필요성과 충분성을 혼동하지 않는다.

따라서 현 단계 판정은 **“논리·출처·재현자료를 갖춘 팀 검증용 투고 후보본”**이다. 심사자가 재계산할 수 있는 핵심 자료는 준비됐지만, 두 명의 독립 검토, 서비스 도메인 외적 타당성, 저자·이해상충·연구비 정보, KCI 유사도 결과와 학회 최종 양식은 연구자가 완료해야 한다. 이 외부 게이트 전에는 “그대로 제출 가능한 최종 승인본”이라고 단정하지 않는다.
