## 1. 가장 중요한 결론

1. 한국범죄학회의 학술지 **「범죄와 정책」은 실제로 존재한다.** 2025년 창간된 연 2회 발행 학술지이며 영문명은 *The Korean Crime and Policy Review (KCPR)*이다. 기존 목차의 “학술지를 찾지 못했다”는 문장은 삭제해야 한다.
2. 다만 현재 확인한 공식 KCI 검색 결과만으로는 이 학술지의 **KCI 등재 여부를 확정할 수 없다.** KCI 유사도 검사 제출 의무가 있다는 사실과 KCI 등재는 서로 다른 문제다.
3. `범죄와정책_논문_목차_v2.md`는 완성 논문이 아니라 **정책논문 설계안**이다. 연구질문과 장 구성은 개선됐지만, 현재 실험 라벨이 불안정하여 주요 효과크기와 유의확률을 논문의 결과로 사용할 수 없다.
4. Amazon Bedrock Guardrails의 민감정보 필터는 현재 **한국어를 “Optimized and supported”로 공식 지원한다.** “Bedrock은 영어 중심이고 한국어를 지원하지 않는다”는 일반화는 틀리다. 이 프로젝트에서 관측된 실패는 특정 가드레일 정책·버전·엔터티 설정의 결과로 한정해야 한다.
5. 최종 논문 수치를 만든 `run_e_final_4way.py` 기준으로, 10,000개 변이 페이로드 중 원래 PII 문자열이 입력에 그대로 남지 않은 사례가 5,287개이고 2,647개는 그 평가 규칙으로 정답을 추적할 수 없다. 이 상태에서 산출한 탐지율과 McNemar 검정은 **종속변수의 구성타당도가 확보되지 않았다.**
6. 범죄학 이론은 설명 틀로 사용할 수 있으나, 현재 실험은 실제 범죄자·피해자화·시공간 수렴을 측정하지 않는다. 따라서 “일상활동이론 검증”이 아니라 **“일상활동이론의 보호자 개념을 활용한 가드레일 역량 감사”**로 규정해야 한다.
7. 법조문 인용에는 여러 오류가 있다. 특히 `§71④`가 아니라 **제71조 제4호**, AI 기본법 제33조는 위험관리 의무가 아니라 **고영향 AI 해당 여부 확인**, 위험관리 의무는 제34조다.
8. 동일한 성공 판정 함수가 저장소 안에서 여러 방식으로 구현되어 있다. `analyze_true_detection.py`의 전각·원문자 정규화를 쓰면 A/B/C/D TRUE가 각각 7,901/9,067/9,373/9,711로 달라진다. **평가기 구현이 하나로 고정되지 않은 상태**다.
9. `PII/results/data/payloads_10k.json`은 10,000건이지만 `PII/evaluation/payloads_10k.json`은 3,538건뿐이다. 현재 `make sample` 경로는 이름과 달리 10,000건을 생성하지 못한다.

## 5. 논증 구조 검증

### 5.1 현재 목차가 의도하는 인과 사슬

1. 생성형 AI 서비스에는 한국어 민감정보가 입력·출력·로그·외부 API를 통해 노출될 위험이 있다.
2. 개인정보보호법은 민감정보 처리와 안전조치를 요구하지만, 규범이 구체적 기술 성능을 자동으로 보장하지는 않는다.
3. 가드레일은 일상활동이론의 “보호자” 및 상황적 범죄예방의 표적 강화·접근통제와 유사한 기능을 한다.
4. 동일한 합성 페이로드에 서로 다른 방어 구성을 반복 적용해 보호자 역량 차이를 비교한다.
5. 취약 항목과 잔존 우회를 근거로 기술 최소기준·영향평가·폐쇄망 정책을 제안한다.

이 사슬의 **문제의식과 정책 연결은 타당**하다. 그러나 4단계의 결과 라벨이 불안정하고 3단계의 이론 조작화가 과도해, 현재 형태로는 결론이 전제보다 강하다.

### 5.2 연구질문별 판정

| 연구질문 | 판정 | 이유와 수정 |
|---|---|---|
| RQ1: 민감정보 카테고리에 따라 우회율이 다른가 | 조건부 타당 | 카테고리를 법 제23조·시행령 제18조와 일대일 매핑하고, 변이 후 정답 span을 다시 만들어야 검증 가능 |
| RQ2: Layer 0 추가가 우회율을 낮추는가 | 현재 검증 불가 | 반복측정 구성 비교는 가능하지만 현재 TRUE/FALSE 라벨이 오염됨. 재라벨링 후 효과크기와 신뢰구간을 다시 계산해야 함 |
| RQ3: 필요한 기술·형사정책 대응은 무엇인가 | 규범적 질문 | 실험 RQ가 아니라 법해석·정책분석 질문으로 분리해야 함 |

`준실험`이라는 표현도 부정확하다. 처치 배정의 외생적 준실험이 아니라 동일 페이로드에 구성별 처리를 적용한 **통제된 반복측정 벤치마크**다.

### 5.3 일상활동이론(RAT) 조작화

| v2 조작화 | 판정 | 적절한 표현 |
|---|---|---|
| 동기화된 범죄자 = 변이 L0~L5 | 부적절 | 변이 수준은 공격 기법의 정교도·난이도이지 범죄 동기가 아님 |
| 적합한 표적 = 민감정보 카테고리 | 부분 타당 | 가치·가시성·접근성·관성 등 표적 적합성 차원을 별도 측정해야 함 |
| 유능한 보호자 = 가드레일 구성 | 이론적 유추로 타당 | “수동적 기술 보호자” 또는 “보호자 역량 대리지표”로 한정 |
| 잔존 L5/RAG 우회 = 범죄 전이 | 현재 불성립 | 동일 공격의 전술별 잔존 취약성일 뿐, 공격자의 실제 전술 이동을 관찰하지 않음 |

결론적으로 이 연구는 RAT 자체를 검증하지 않는다. 가장 정확한 설명은 다음과 같다.

> 본 연구는 실제 범죄 발생의 세 요소를 검증하는 연구가 아니라, 일상활동이론의 보호자 개념과 상황적 범죄예방의 표적 강화 개념을 분석 틀로 활용한 한국어 민감정보 가드레일 역량 감사다.

전이를 주장하려면 시간 순서가 있는 적응형 공격 실험이 필요하다. 예를 들어 공격자 역할의 참가자 또는 에이전트가 Layer 0 도입 전후 어떤 전술로 이동하는지, 성공률·비용·시간이 어떻게 변하는지를 관찰해야 한다.

## 6. 코드·데이터·실험 재현 검증

### 6.1 데이터셋 구성

- `payloads_10k.json`: 10,000개
- PII 유형: 95개
- 변이 이름: 36개
- 원래 `pii_value`가 변이된 입력에 정확히 존재하지 않음: 5,287개(52.87%)
- 최종 평가기의 원문/숫자 완화 추적까지 적용해도 추적 불가: 2,647개(26.47%)

추적 불가 사례의 분포:

| 구분 | 추적 불가 수 |
|---|---:|
| L1 | 2,134 |
| L2 | 161 |
| L3 | 99 |
| L4 | 253 |
| format 그룹 | 1,511 |
| checksum 그룹 | 937 |
| semantic 그룹 | 199 |

여기서 2,647개는 최종 논문 수치를 만든 `run_e_final_4way.py`의 원문·숫자 비교 규칙에 대한 값이다. 저장소의 다른 분석기 `analyze_true_detection.py`는 전각 숫자와 원문자 숫자를 추가 정규화하여 입력 추적 불가를 1,339개로 계산한다. 어느 쪽도 변이 후 gold span을 직접 사용하지 않으며, 동일 데이터에 서로 다른 판정 규칙을 적용한다.

최종 평가기는 레이어 출력이 달라지고 원래 `pii_value`가 출력에 없으면 성공으로 판정할 수 있다. 따라서 변이된 실제 PII가 그대로 남았는데도 다른 문자열만 바뀌었거나 원본 문자열 비교가 실패한 사례가 TRUE에 섞일 수 있다.

|---|---:|---:|---:|
| A baseline | 8,015 | 80.15% | 2,370 (29.57%) |
| B +L4 | 9,096 | 90.96% | 2,458 (27.02%) |
| C +L0 | 9,432 | 94.32% | 2,492 (26.42%) |
| D full | 9,723 | 97.23% | 2,550 (26.23%) |

이 수치는 파일에 기록된 결과를 재현한 것이지, 올바른 탐지율을 확인한 것이 아니다. TRUE 사례의 약 26~30%에서 정답 추적 자체가 불가능하므로 “Layer 0가 몇 %p 개선”, “p < 10⁻²⁸”과 같은 주 결론은 보류해야 한다. McNemar 공식이 맞아도 입력된 쌍별 라벨이 타당하지 않으면 유의확률은 연구 질문에 답하지 못한다.

`analyze_true_detection.py`의 다른 정규화 규칙으로 같은 저장 결과를 다시 분류하면 A/B/C/D TRUE는 각각 **7,901/9,067/9,373/9,711**이 된다. 최종 논문 수치인 8,015/9,096/9,432/9,723과 다르므로, 논문은 먼저 하나의 mutation-aware 평가 명세와 단일 구현을 고정해야 한다.

필수 수정은 각 변이기가 다음을 함께 내보내도록 하는 것이다.

- 변이 후 정확한 PII span
- canonical value
- 허용되는 동치 표현
- 변이 provenance
- expected action(탐지·마스킹·차단)

그 후 전체 10,000건을 재평가하고, 난이도·유형별 사람 이중검토 표본과 일치도를 보고해야 한다.

### 6.3 추가 수치·구현 오류

| 항목 | 논문/문서 주장 | 검증 결과 | 판정 |
|---|---|---|---|
| VIN 체크섬 | 유효한 합성 값 | VIN 72개 행(고유값 10개) 모두 49 CFR Part 565의 제9자리 check digit 실패, 모두 valid로 표기 | 실패 |
| Layer 0 패턴 수 | 42개 | 코드상 정규식 패턴 45개, 키워드 카테고리 22개 | 수정 필요 |
| L0 지연 | 매우 낮음 | 평균 52.21ms, 중앙값 48ms, p99 135ms | 재현 |
| L4 지연 | L0 대비 약 220배 | 평균 1542.09ms, 중앙값 1257ms, p99 4164ms; 평균비 약 29.5배 | 실패 |
| 구성 C 비용 | `$0.08` | C에는 L4가 없으므로 해당 비용 귀속 불가 | 실패 |
| Smart Cascade 비용 | 명칭 혼재 | 약 568회 L4 호출에 대한 `$0.08`로 해석 가능 | 명확화 |
| 탐지기 수 | 문서 간 불일치 | 코드 기준으로 통일 필요 | 수정 필요 |

VIN 계산 기준은 [NHTSA의 VIN 안내](https://www.nhtsa.gov/document/vehicle-identification-number-vin)와 [49 CFR Part 565 공식 규정](https://www.govinfo.gov/content/pkg/CFR-2019-title49-vol6/pdf/CFR-2019-title49-vol6-part565.pdf)이다. 제9자리를 제외하고 정해진 문자값과 위치별 가중치를 곱해 합산한 뒤 11로 나눈 나머지를 제9자리와 비교했다. 형식과 체크디지트 통과만으로 실제 제조사에 배정·발급된 VIN임이 입증되는 것은 아니다.

### 6.4 재현성

`make all`은 현재 완전 재현되지 않는다. 기본 정책이 `required`인 필수 파일 `PII/fuzzer/data/tagged_korean_names.jsonl`과 `PII/fuzzer/data/tagged_korean_addresses.jsonl`이 4개 저장소와 확인한 109개 원격 ref 어디에도 없고, `sample` target도 이를 생성하지 않는다. fuzzer는 이 파일이 없으면 `RuntimeError`를 발생시킨다.

공개 코드의 Layer 0·fuzzer 테스트를 격리 환경에서 실행한 결과는 **123 passed, 8 failed**였다. 실패 8건은 모두 위 파일 부재와 연결된다. 따라서 논문에는 “완전 재현 가능”이라고 쓰지 말고, 다음을 먼저 고쳐야 한다.

또한 이름이 같은 표본 파일 두 개가 서로 다르다.

| 경로 | 실제 payload 수 | 메타데이터 |
|---|---:|---|
| `PII/results/data/payloads_10k.json` | 10,000 | `count: 10000`, PII 유형 95개 |
| `PII/evaluation/payloads_10k.json` | 3,538 | `count: 3538`, PII 유형 91개 |

`Makefile`의 `sample` target은 fuzzer를 `--count 3`으로 호출한 뒤 `sample_10k.py`를 실행한다. `sample_10k.py`는 원천 집합보다 많은 행을 복원하지 않으므로 현재 경로의 결과는 3,538건에 그친다. 누락 코퍼스를 복원하더라도 이 target만으로 논문이 사용한 10,000건을 재생성할 수 없다.

1. 파일을 비식별·라이선스 확인 후 저장소에 포함하거나 재생성 스크립트 제공
2. SHA-256 및 데이터 버전 기록
3. 의존성 lockfile과 실행 명령 고정
4. 원시 입력부터 표·그림까지 한 번에 재생성하는 깨끗한 환경 CI 제공
5. `make sample`이 정확히 10,000건을 생성하고 그렇지 않으면 실패하도록 검증(assertion) 추가
6. 평가 함수들을 하나의 canonical evaluator로 통합

### 6.5 데이터·지식베이스

데이터 저장소의 유일한 파일 `curated/curated_weak_t0.92.json`은 `source="weak"`, threshold 0.92, `kept_ids=1,997`만 제공한다. 원자료, 모델 출력, 사람 검토 라벨, 제외 사유가 없어 큐레이션을 독립적으로 검증할 수 없다.

지식베이스에는 8,400건과 10,000건 실험 서술이 혼재하며 스스로 정합성 확인 필요 상태로 표시되어 있다. 논문은 10,000건 최종 실험만 기준으로 고정하고, 8,400건은 파일럿으로 명시하거나 제거해야 한다.

## 7. Bedrock·Presidio·LiteLLM 관련 주장 검증

### 7.1 Amazon Bedrock Guardrails

AWS 공식 문서는 민감정보 필터에서 한국어를 **Optimized and supported**로 명시한다. 이는 해당 정책의 기반 모델이 한국어에 맞게 조정되고 테스트되었다는 AWS의 정의다.

- [AWS: Languages supported by Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-supported-languages.html)

따라서 아래 표현은 사용하면 안 된다.

- “Bedrock은 한국어 PII를 지원하지 않는다.”
- “Bedrock은 영어에만 튜닝되어 한국어 재현율이 낮다.”
- “상용 가드레일은 거의 예외 없이 영어 중심이다.”

가능한 표현:

> Amazon Bedrock Guardrails는 현재 한국어 민감정보 필터를 공식 지원한다. 본 연구의 결과는 실험 당시 사용한 특정 guardrail ID·version·sensitive-information policy·entity 설정 및 평가일에서 관측된 우회 성능이며, 제품 전체의 한국어 지원 여부를 뜻하지 않는다.

논문에 반드시 기록할 항목:

- AWS 리전
- guardrail ID와 version
- safeguard tier
- enabled policy와 entity 목록
- request/response 적용 위치
- 평가 날짜
- API 모델·LiteLLM 버전

### 7.2 Presidio

현재 Presidio 공식 문서는 한국용 recognizer로 `KR_DRIVER_LICENSE`, `KR_FRN`, `KR_PASSPORT`, `KR_BRN`, `KR_RRN`을 열거한다. Presidio는 다국어 및 사용자 정의 recognizer를 지원하지만 모든 민감정보를 반드시 찾는다고 보장하지는 않는다.

- [Presidio supported entities](https://microsoft.github.io/presidio/supported_entities/)
- [Presidio Analyzer](https://microsoft.github.io/presidio/analyzer/)

따라서 Presidio의 현재 일반 능력, 본 프로젝트가 고정한 버전, 프로젝트가 실제 활성화한 recognizer를 분리해야 한다.

### 7.3 LiteLLM

내부 환각 검증문서의 `LiteLLM Guardrail Policies and Korean PII Masking v2`는 실재하는 논문·공식 보고서 제목으로 확인되지 않았다. LiteLLM은 가드레일과 Presidio 등을 연결하는 게이트웨이이므로, 탐지 성능 주장은 LiteLLM 자체가 아니라 연결한 엔진·버전·언어·recognizer 설정에 귀속해야 한다.

## 12. 수정 우선순위

### P0 — 결과를 쓰기 전에 반드시 해결

1. 변이 후 정답 span과 canonical value를 생성하도록 데이터 파이프라인 수정
2. 평가 함수들을 하나의 mutation-aware canonical evaluator로 통합
3. 전체 10,000건 재라벨링·재평가
4. VIN 등 생성기와 체크섬 전수 수정
5. 탐지율·효과크기·McNemar·비용·지연 표 전부 재생성
6. Bedrock 한국어 미지원/영어 전용 일반화 삭제
7. 누락 데이터 파일과 10,000건 표본 생성·재현 파이프라인 복구

### P1 — 투고 원고 작성 전에 해결

1. RAT 검증이 아닌 보호자 역량 감사로 연구 범위 재규정
2. `준실험`, `동기화된 범죄자=변이 수준`, `잔존 우회=전이` 표현 수정
3. 개인정보보호법과 AI 기본법 조문·제재 구조 교정
4. 환각 참고문헌 제거 및 정확한 서지로 교체
5. 국내 문헌을 이론 조작화·반대 결과와 연결하고 단순 나열을 피할 것
6. 선행연구 검색식·DB·기간·배제기준을 공개해 제한된 신규성만 주장
7. KCI 등재 상태 공식 확인

### P2 — 제출 직전

1. 최종 코드·데이터 commit과 원고 수치 동결
2. 표·그림과 원시 결과의 자동 대조
3. 이해상충·연구윤리·이중용도·합성데이터 고지
4. 학회 HWP 형식, 분량, 유사도, 회원 요건 확인
5. 법령과 벤더 문서 접근일 최종 갱신

## 13. 최종 판정

논문의 주제는 「범죄와 정책」의 범위에 들어가며, 한국어 민감정보 방어와 법적 안전조치 사이의 간극을 형사정책적으로 분석하려는 문제의식도 의미가 있다. 외국 범죄학 핵심 문헌과 학술지 자체도 실재한다.

그러나 현재 주요 실험 결과는 변이 후 정답을 안정적으로 추적하지 못하는 평가기 때문에 논문의 핵심 결론을 지지하지 못한다. 여기에 Bedrock 한국어 지원에 대한 사실 오류, 법조문 번호·제재 구조 오류, RAT·전이의 과도한 조작화, 재현 파일 누락, 기술 참고문헌 환각이 겹쳐 있다.

따라서 현 상태는 **“조건부 적합”보다 “대폭 수정 없이는 부적합”에 가깝다.** P0를 먼저 해결해 수치를 다시 만든 뒤, P1의 이론·법·서지 교정을 완료해야 실제 원고 작성과 투고 판단으로 넘어갈 수 있다.
